# Source96 secondary inference: K16 parity, K94, header-gated approximate L/R mirror TTA (2026-10-12)

Status: implemented and tested on synthetic data on CPU (plus a check that the pinned real audit artifacts verify under the frozen pins). Not run on the real 96-slot cache, not run on a GPU, not competitively evaluated. The mirror is an **approximate** L/R mirror: it is not verified (`mirror_orientation_verified: false`) and the geometry is not verified universally (`universal_geometry_verified: false`); runtime is unmeasured. Code: `knee/source96_secondary_inference.py`; tests: `tests/test_source96_secondary_inference.py`.

## Outputs, modes and their role

One frozen checkpoint (top-3 SWA CoAtNet `RaptorClassifier`, 224, trained at K8, selected at K16), one pass over the same fixed fold-0 development studies. The CLI requires exactly one explicit mode:

| Mode (CLI flag) | Arms written | Mirror | Needs routing artifacts |
|---|---|---|---|
| `plain_only` (`--plain-only`) | `k16_plain`, `k94_plain` | none | no: never read |
| `header_gated_approx_lr_tta` (`--header-gated-tta`) | `k16_plain`, `k94_plain`, `k94_header_gated_approx_lr_tta` | `mirror_ok` studies only | yes: the three pinned audit files |
| `ungated_mirror_tta` (`--ungated-mirror-tta`) | `k16_plain`, `k94_plain`, `k94_mirror_tta` | every study, headers ignored | no |

- `k16_plain`: same arithmetic as the primary export; parity check (tolerance 1e-4 against `oof_fold0.csv`, same-hardware FP16), first and fail-closed in every mode.
- `k94_plain`: every interior triplet of the 96-slot stack.
- `k94_header_gated_approx_lr_tta`: for studies routed `mirror_ok` the equal 50:50 mean of plain and approximate-L/R-mirrored K94; for every `bypass_plain` or `needs_transform` study the identical plain K94 row, byte-for-byte equal to `k94_plain` (checked in the run and in the receipt). The full development membership is kept, nothing is dropped, no weight is selected, no threshold is tuned on labels.
- `k94_mirror_tta` is the LEGACY, UNGATED arm: it mirrors every study regardless of its headers. It stays computable for historical comparison only; its receipts keep their original semantics (`version source96-secondary-inference-v1`, `ungated: true`, `orientation_audit_required_before_tta_interpretation`) and are not reinterpreted by the audit. Gated and plain-only receipts carry `version source96-secondary-inference-v2` and `mode`.

All arms are secondary diagnostics. The frozen K16 primary endpoint governs promotion. The fold-0 development set is exposed (selection used it), so differences between arms are descriptive only: no epoch, target, weight or blend selection may use them. Adopting K94 or any mirror for a submission would be a separate, pre-declared decision. **Geometry alone does not establish label invariance or an accuracy benefit.** A header-consistent study still gets only an approximate mirror, and whether a mirrored knee keeps its labels (each structure keeps its identity, a medial structure stays medial) is an assumption of the mirror, not something the header audit measured.

## Header-gated routing

Source: the label-blind DICOM orientation audit (`orientation-audit-kernel-v2`, headers only, no labels, no pixels, no identifiers in the aggregate). Train result: 4407 studies, 20792 selected series; study routes 4128 `mirror_ok`, 279 `bypass_plain`, 0 `needs_transform`; all 3 visible-test studies `mirror_ok`. A study is `mirror_ok` only if every present selected series is `ok_standard` (assumed mirror vector L/R, standard class, complete consistent geometry, unambiguous ascending order); anything else, including any oblique series, is `bypass_plain`; `needs_transform` marks clean geometry whose L/R vector is another image axis (a flip exists but is not the assumed one, and it is never applied here: such studies are bypassed).

**The frozen 99% cohort descriptor FAILED for all three planes** (share of studies whose selected series in the plane are all `ok_standard`): sagittal 95.462%, coronal 97.164%, axial 98.162%. The threshold is frozen and is not relaxed. Therefore the mirror must not be called universally verified: every receipt records `mirror_orientation_verified: false`, `universal_geometry_verified: false` and the three shares with `passes_99_percent: false`. Per-study routing governs which studies are mirrored; the cohort descriptor is descriptive only and does not certify any individual study.

Routing semantics (`run_secondary(mode='header_gated_approx_lr_tta', routing=...)`):
1. `load_routing_artifacts` verifies the pinned artifacts (below) before the corpus is opened (CLI: after the checkpoint bind, before `staged_corpus`).
2. `join_routes` joins routes to the evaluation study IDs by an explicit, checked ID lookup, never by position. It refuses missing routes for any evaluation study and duplicate evaluation IDs, and accepts only a `VerifiedRouting` (a plain dict is refused). It runs before the output directory is created. `VerifiedRouting` is immutable: its route map is a read-only `MappingProxyType` over a private copy, attributes cannot be assigned or deleted (slots plus blocked `__setattr__`/`__delattr__`), and the nested counts, descriptor, pins and receipt are stored as frozen JSON and returned as copies. The content binding is also re-checked from the payload at construction and at every `join_routes` call: the ID-order hash, the route-array hash and the route counts are recomputed and must equal the stored values and the pins, so an edit behind the read-only view, a replaced route map, or a forged object carrying altered routes with the original hashes is refused.
3. `mirror_ok` studies get the mirrored K94 view and the equal mean; the other studies are not even mirrored (no mirrored windows are built for them) and their row is the `k94_plain` row. Window plans for `k94_mirror_view` therefore cover only the eligible studies.
4. The receipt records `routing.full_population` and `routing.eligible_subset` (study counts and order-sensitive `ids_sha256`), `routing.route_counts` for the development population, the audit's population route counts, the artifact pins and the descriptor. No study identifiers appear in any receipt.

## Plain-only mode

`--plain-only` (`mode='plain_only'`) runs K16 parity (fail-closed, 1e-4) and K94 plain with no TTA, no mirror and no routing: the routing files are not read, `load_routing_artifacts` and `join_routes` are not called, and the CLI rejects orientation-artifact flags in this mode. It is also the **Python API default**: `run_secondary` called without `mode` runs plain-only and can neither mirror nor open routing (regression-tested); historical callers must request `mode='ungated_mirror_tta'` explicitly, and the CLI still requires an explicit mode flag. A future competition entry must audit the unseen test headers at runtime rather than reuse the train routes or the three visible-test routes. Use it when the gating artifacts are not available; the checkpoint binding, equal view weights, missing-plane and window masks and state checks are the same as in the other modes.

## Descriptive plain-versus-gated comparison (computes only)

`compare_plain_vs_gated(labels, label_mask, plain, gated, eligible)` returns, for the full population and for the eligible subset, per-target AUC with support, positive and negative counts for plain K94 and gated TTA, undefined targets listed, an unweighted macro over defined targets and the gated-minus-plain difference. Labels and masks are supplied later by the caller; the helper requires binary labels and masks, finite probabilities and gated rows byte-equal to plain on non-eligible rows, never mutates its inputs, and selects, thresholds or tunes nothing. Tested on synthetic labels only. Differences on the exposed development set are descriptive.

## Mirror derivation per plane (assumed standard orientation, unverified)

This section derives the mirror from the reader code plus the standard-IOP assumption; it was written before the header audit and is itself not a measurement (the cache stores no `ImageOrientationPatient`). The later label-blind header audit (see Header-gated routing) measured the geometry of the selected series and gates which studies are mirrored, but it does not turn the derivation into a verified, universal or label-preserving mirror. Every receipt carries `mirror_orientation_verified: false`.

Layout (`knee/source_span_pilot.py:18`, same list in `knee/source96_cache.py:20-21`): `SLOTS96 = Sagittal/fluid 26, Sagittal/non-fluid 22, Coronal/fluid 18, Coronal/non-fluid 12, Axial 18`, i.e. slots at indices 0-25, 26-47 (sagittal, 48 slices), 48-65, 66-77 (coronal, 30), 78-95 (axial, 18); depth 96. The module derives its layout from that constant and refuses to import if it changes.

Reader convention (the cache reader is the pinned public reader, SHA `859aae12...` = `knee/corpus44_parity.py:20`, re-parameterised only by slots, depth and span in `knee/source_span_pilot.py:31-70`; local copy `outputs/research/2026-10-08/raptor-audit/knee-mri-twelve-findings-from-a-single-model.py`):
- Slices of a series are sorted by `dot(IPP, cross(row_cosines, col_cosines))`, ascending (`:268`, `:275`): the stack axis is the series normal. Slot slices are then picked with `linspace` over that order (`:319-320`).
- Pixels are used as stored: crop a centred square of 140 mm and resize to 336 (`:286-290`); there is no transpose, rotation or IOP-based reorientation. Array axis 1 is DICOM rows, axis 2 (width) is DICOM columns, which run along the first IOP triple.
- Under standard IOP (axial `1,0,0,0,1,0`; coronal `1,0,0,0,0,-1`; sagittal `0,1,0,0,0,-1`) this gives:

| Plane | Stack (slice) axis | Image width axis | L/R mirror under the assumption |
|---|---|---|---|
| Sagittal | patient L/R (normal along x) | A/P | reverse the slice order of that slot; slice content unchanged |
| Coronal | A/P | L/R | flip width; slice order unchanged |
| Axial | S/I | L/R | flip width; slice order unchanged |

Under this assumption a uniform horizontal flip would be wrong for sagittal (it would flip A/P). Reversal is per slot, never over all 48 sagittal positions, because the two sagittal slots are different series. The mirror is applied to the uint8 volume and the mask before windowing and normalisation (mirror the stack, then normalise; `mirror_volume` in `knee/source96_secondary_inference.py`), and window centres are re-planned from the mirrored mask by the unchanged eval policy.

Raptor comparison (untrusted reference text, read only: `_mirror_tri`, lines 270-276 of the scratchpad `velciraptor.py`): centre slot decides, sagittal reverses the 3 channels at the same centre, coronal/axial flip width. `test_full_valid_synthetic_reflected_centre_comparison_with_public_raptor_rule` is a full-valid synthetic reflected-centre comparison: with every slice populated, it compares that shortcut's window with the triplet at the reflected centre of the mirrored volume. They coincide for every window that lies inside one series (86 of 94 K94 centres) and for the four straddling windows that are purely coronal/axial (centres 65, 66, 77, 78), so 90 of 94; they differ by construction for the four windows centred at 25, 26, 47, 48 that involve a sagittal slice across a series boundary, which are already cross-series mixtures in the plain pass. This is not a proof that the sampled bags of the two constructions are identical: with missing or partial planes the mirrored mask re-plans the centres (different valid range, different `linspace`), and that case is not covered by the comparison. The `RaptorClassifier` head pools windows with a softmax over the window axis (`train_knee.py:353`), so window order does not matter. The study-level form was chosen because it is the direct statement "this study with the assumed L/R axis reflected, through the same pipeline", including partial-mask planning.

## Missing-slot policy

- Cache masks are 1 where a slice has any nonzero pixel (`pilot.validate_arrays`). A missing series zero-fills its whole slot; a failed frame leaves one zero slice (`:310-315`, `:336`).
- Mirror permutes volume and mask together: masked slices stay zero and masked, valid slices stay valid; a plane with no valid slices stays empty; nothing is written into masked positions. Pixel/mask consistency holds after mirroring (tested, including a partially valid sagittal slot, whose valid run moves to the other end of that slot).
- Centres use the pinned `StudyWindows._centers` eval policy unchanged (valid min/max, neighbours in range, `linspace().round()`, duplicates kept, fewer than 3 valid slices falls back to slices 0-2). Masked and cross-series triplets are kept as in the primary path and counted in the receipt (`masked_triplets`, `boundary_triplets`, `duplicate_centers`, `fallback_studies`); a second, independent implementation of the policy must agree with the pinned sampler or the run stops.
- Whole-empty or pixel/mask-inconsistent studies stop the run (fail-closed receipt).

## Checkpoint binding

The frozen primary is bound and qualified before anything opens the corpus. In the CLI the order is: (1) `bind_checkpoint` loads the SWA file (`weights_only=True`), checks arch, res 224, target order, top-3 `swa_over` and finite weights, hashes the file, then calls the existing `export_guard(..., secondary=True)` (`knee/source96_training.py`): ten completed epochs, `run_fold0.json` has `export.k_eval == 16`, its `checkpoint_sha256` equals this file's SHA-256 and its `selected_epochs` equal the checkpoint's; (2) the pinned trainer definitions are loaded and their digest enforced; (3) only then `guard.staged_corpus()` and `guard.verify_export_inputs` (which also opens the corpus) run; (4) `run_secondary` binds the checkpoint again immediately before inference. A missing, K16-mismatched, SHA-mismatched or tampered primary record raises `ValueError` before step 3, and `test_cli_invalid_primary_cannot_open_the_corpus` spies on `staged_corpus`, `verify_export_inputs` and the loader's `open_corpus` to prove none is called. The aggregate `receipt.json` records the file SHA-256, the primary record's SHA, selected epochs and a model state digest before and after the run; each output carries the same `checkpoint_sha256`, and each `.npz` embeds it. The file is re-hashed after inference.

K16 parity against `oof_fold0.csv` is on by default and is a real gate that runs first. The order inside `run_secondary` is: (1) the complete K16 pass over the full fixed membership (the only phase that validates studies and plans K16 windows); (2) the parity check on that complete K16 output, tolerance 1e-4; (3) only if it passes (or `--no-enforce-parity` was given) K94 plain and, in the mirrored modes, the mirrored view of the eligible studies; (4) all arm files are written together at the end. On an enforced mismatch the run raises `ValueError` after writing **only `receipt.json`**: `status: PARITY_FAIL`, the parity diagnostics (maximum absolute error, tolerance, reference file hash), the K16 window plan, `outputs: {}` and `k94_and_mirror_views_run: false`. No K94 or mirror window is planned or forwarded (no mirror function is even called) and no arm output is written, **the K16 output included**, so a K16 that failed parity cannot be mistaken for a usable output. With `--no-enforce-parity` the mismatch (`enforced: false`, `within_tolerance: false`) is recorded and the run continues with phase 3. `saved_primary` validates the reference before it is compared: exact header, well-formed rows, no duplicate validation rows (a duplicate cannot hide behind a complete ID set), exactly the evaluation ID set (no missing, no unexpected IDs), and every probability finite and within [0, 1]. A corrupt reference raises `ValueError` after the K16 pass and before any K94 work, even with `--no-enforce-parity`, leaves a `FAIL` receipt and writes no arm output. Spy tests count the forward calls: a mismatch in every mode performs only the three K16 forwards of the five-study fixture (zero K94 or mirror forwards, only K16 center plans) and leaves a directory holding just `receipt.json`; a pass performs all K16 forwards before any K94 forward and yields results byte-identical to a run without a reference, bypass rows included.

## Runtime (unmeasured)

Forward-window counts per study: K16 = 16 windows; K94 = 94 windows (94/16 = 5.875 times the windows of K16); the mirrored K94 view is 94 more. The legacy ungated pass forwards 204 windows per study (12.75 times the windows of the primary K16 alone); `k94_mirror_tta` on its own is 188 (11.75 times); the plain K94 view is shared with `k94_plain`. `plain_only` forwards 110 windows per study, and the gated pass forwards 110 plus 94 per `mirror_ok` study (so 204 for a fully routed study, fewer in proportion to the bypassed share). These are window-count ratios, not time estimates.

No wall-time estimate is made. No 96-slice or A100 secondary throughput has been measured, and the only nearby measurement, the old 44-slice K16 diagnostic (283.49 s including setup), does not transfer: different slice count, setup share and hardware. Time is not linear in forward windows alone: single-thread CPU window construction (resize and normalisation per window), the per-study mirrored-volume copy, lazy cache reads and the K94 one-study-per-forward grouping all contribute. Runtime will be recorded from the first receipt, which writes `elapsed_seconds`, per-arm `seconds` (window construction plus forward) and `peak_host_rss_bytes`, plus peak CUDA memory on CUDA. K94 views run one study per forward with `--k94-win-chunk 16` (memory bounded below the primary's 64-window forward); K16 uses the primary grouping (4 studies, `win_chunk` 0).
