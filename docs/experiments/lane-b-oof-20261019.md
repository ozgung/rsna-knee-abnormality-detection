## Method

- **Rendering.** Each study was rendered once on a Colab A100 through heliosli's pinned `compact_infer.CStudies`. The source hashes match the R6 profile pins. The pipeline is: native render → geometry → image side check (`side_cls.pt`, the same file in R6 and R7) → SKM-TEA anchors → v4 rows at 384 px → D2 fluid volumes. The DICOMs were range-read per study from the official archive and deleted after rendering.
- **GPU passes.** Each fold model ran the eager forward that compact_infer v4c uses: bf16, chunk 192, centre crop 352, return_aux state read-out, fp32 rescue (never triggered).
  - R6: plain pass + mirrored pass (combined as `score_v4c`).
  - R7: plain pass. R7 flip was recorded only for the first 49 gold studies. It was dropped because the run was GPU-bound and the plan made it optional.
- **Model choice per study.** Each pool study uses its hash-fold model only, `sha1(uid)[:8] % 4` (`compact_train.py:2015`). Gold uses all four fold models. A 200-study pool sample also got all four plain passes for the mapping check.
- **Stackers.** The fluid stacker (Effusion) and state stacker (Baker's) were applied offline from the recorded logits, state read-outs and volumes.
- **Parity.** heliosli's `compact_infer.main()` was run unchanged on gold-58 (four models, eager): R6 with `--flip-tta`, R7 plain. The driver reproduces its `predictions.csv` within a maximum |Δp| of 8.2e-8 for both bundles, stackers included.
- **Truth and statistics.** Truth on the pool is `labels_v1_blend >= 0.5`. Macro is the mean of 12 per-target AUCs. CIs come from a paired study bootstrap: 2,000 draws, seed 42 (`knee.paired_validation`).
- **Code.** `scripts/laneb/` (`vm_oof_infer.py`, `vm_gold_parity.py`, `analyze_oof.py`, `build_labels_v3.py`, `build_targets_v3.py`).

## Caveats for the selection

- **The OOF comparison uses single-fold-model columns.** The dual pairs two different models. R6 flip is one model with test-time augmentation (TTA). The deployed P6 and P2 each average four fold models first, which captures part of the variance reduction the dual gets in the OOF setting. The OOF Δ (+0.0029) is therefore an upper-side estimate of the deployed gain. The only four-model read-out (gold-58, n = 58) has the opposite sign, with a CI that includes 0. This setup cannot measure the deployed Δ out of fold, because a four-model mean is in-sample for three of the four models. Treat the rule as met, with this caveat stated next to it.
- **Pooled AUC mixes four fold models' score scales.** The per-fold deltas agree in sign.
- **Truth is a weak report-derived table** (`labels_v1_blend >= 0.5`). R6 and R7 were trained on different report-derived targets.
- **The stackers were fitted by heliosli on the training pool** (2 classes, 3–7 coefficients).
- **R7 flip was not measured on the pool.**
